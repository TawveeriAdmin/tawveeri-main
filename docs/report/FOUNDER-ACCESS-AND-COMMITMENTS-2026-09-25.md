# الالتزامات والاشتراكات + دخول المؤسس — تقرير قصير (ADR-384، 25 سبتمبر 2026)

## أولًا: هل المصروفات الحالية قيود تاريخية أم جداول متكررة؟
**قيود تاريخية فقط.** كل الـ38 قيدًا مسجلة كمدفوعات فعلية بتواريخها؛ لم يكن يوجد أي جدول اشتراك متكرر. لذلك أُضيف قسم **«الالتزامات والاشتراكات الشهرية»** في صفحة المصروفات، منفصلًا عن المصروفات المدفوعة.

## ما نُفّذ في المال
| القاعدة | التنفيذ |
|---|---|
| الاشتراك المتكرر ينشئ قيدًا متوقعًا في التجديد ولا يصبح مدفوعًا إلا بتأكيد | قيد بحالة **متوقع** يظهر في «قيود متوقعة بانتظار التأكيد» مع زر **تأكيد الدفع (فاتورة/خصم)** يطلب تاريخ الخصم ومرجعه؛ حتى ذلك الحين لا يدخل النقد ولا تكلفة الفترة |
| لا تكرار تلقائي لـRailway/Supabase/SendGrid/Anthropic API | مسجلة كـ**متغير — ميزانية تقديرية** (متوسط آخر 3 فواتير مدفوعة: Railway 338.63، Supabase 131.55، SendGrid 131.06، Anthropic 53.91 ر.س/شهر) — تُدخل الفاتورة الفعلية شهريًا |
| اشتراكات ثابتة قابلة للمراجعة | Claude Max 5x 499.99 (التجديد 2026-10-03)، ChatGPT Plus 89.99 (2026-10-20 — آخر شراء مثبت 2026-07-20، راجعه)، X Premium 15 (2026-10-11) |
| Store Leads وBrowserless | حالة **يحتاج تأكيد المؤسس** — لا يُنشأ لهما أي قيد حتى تغيّر الحالة إلى «فعال» |
| تقرير المصروفات | `/ar/admin/founder/expenses/report` — فلاتر: هذا الشهر / الشهر السابق / منذ البداية / فترة مخصصة؛ أعمدة: الفعلي، المتوقع، الميزانية، الفرق، والتصنيف (بنية / AI / تسويق / تطوير خارجي) |

القيود المتوقعة تُنشأ تلقائيًا (عند فتح الصفحة وبواسطة عامل الخلفية كل ساعة) ولا تتكرر للفترة نفسها.

## ثانيًا: دخول المؤسس
| المطلوب | الحالة |
|---|---|
| `https://tawveeri.com/founder` | **منفذ** — مسجل بدور مدير: مباشرة إلى `/ar/admin/founder`؛ غير مسجل: صفحة الدخول ثم عودة تلقائية؛ مستخدم عادي: صفحة رفض صلاحية بلا أي بيانات إدارة (ويُسجل تنبيه أمني) |
| returnUrl آمن | **منفذ** — يُقبل المسار الداخلي فقط؛ `https://…` و`//…` و`/%2F%2F…` تُتجاهل (اختبار وحدة + متصفح) |
| تذكر هذا الجهاز 30 يومًا كحد أقصى | **منفذ** — الخانة الموجودة أصبحت فعلية: مؤشر = جلسة 30 يومًا كحد أقصى؛ غير مؤشر (الافتراضي، للجهاز العام) = جلسة تنتهي بإغلاق المتصفح. `sameSite=lax` و`secure` على https. **httpOnly غير ممكن** لأن عميل Supabase في المتصفح يحتاج قراءة الكوكي — وهذا مذكور لا مخفي |
| إبطال الجلسات | **منفذ** — في قائمة الحساب داخل لوحة الإدارة: «إنهاء الجلسات على جميع الأجهزة» |
| الدخول بالبصمة/Face ID | **غير ممكن حاليًا** — Supabase Auth لا يدعم Passkeys/WebAuthn؛ لم يُبنَ بديل مزيف |
| زر واضح على الجوال | **منفذ** — زر «مركز قرارات المؤسس» في رأس لوحة الإدارة على الجوال (يختفي داخل المركز نفسه) |
| الاختبارات | **منفذة** — مؤسس مسجل (Chrome سطح المكتب + محاكاة iPhone Safari)، مؤسس غير مسجل، مستخدم عادي (حساب مؤقت أُنشئ وحُذف)، ثلاث صيغ returnUrl خبيثة، وسياسة الكوكيز بعد تجديد قسري. لم يتوفر iPhone حقيقي؛ Safari مُحاكى بوكيل المستخدم وأبعاد الشاشة |

**عيب وُجد وأُصلح أثناء الاختبار:** كانت الوسيطة تنسخ الكوكيز على التحويلات بالاسم والقيمة فقط فتضيع Max-Age وSameSite — أُصلح بنسخ الكوكي كاملًا.

## كيف أستخدمه
1. افتح `tawveeri.com/founder` من أي جهاز. إن لم تكن مسجلًا سجّل الدخول وستعود تلقائيًا إلى المركز. على جهاز عام اترك «تذكر هذا الجهاز» غير مؤشر.
2. في المصروفات: راجع «الالتزامات والاشتراكات الشهرية»؛ عند وصول فاتورة Claude/ChatGPT/X اضغط **تأكيد الدفع** على القيد المتوقع وأدخل تاريخ الخصم ومرجعه. فواتير Railway/Supabase/SendGrid/Anthropic أدخلها شهريًا بـ«إضافة مصروف».
3. لتفعيل Store Leads أو Browserless كالتزام متكرر: عدّل الحالة إلى «فعال» وضع تاريخ التجديد.
4. للخروج من كل الأجهزة: قائمة الحساب ← «إنهاء الجلسات على جميع الأجهزة».
